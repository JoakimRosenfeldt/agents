# Scannable UI

Identify what the user arrives looking for. Inspect the whole screen and a representative repeated item. Apply the relevant rules within the existing design system.

1. Align repeated labels, values, and actions to shared edges. Headings, avatars, and preceding rows can supply those edges. Keep descriptions left-aligned and amounts right-aligned where this helps comparison. Fix floating controls by rearranging content before adding filler.
2. Group by the attribute users search for, such as due date or owner. Use headings, avatars, or categories to distinguish groups. Keep useful density. Extra whitespace can lengthen a list without making it easier to search.
3. Replace reading with recognizable visuals where useful. Use familiar symbols, diagrams, and established link styling. Keep exact values needed for comparison. Label ambiguous icons visibly; a tooltip should not be required to understand an action.
4. Keep useful actions near their content. Let category chips offer direct editing where appropriate. Do not hide controls in menus solely to tidy the layout or add chips that communicate nothing.
5. Keep defaults quiet. Reserve emphasis for selected, changed, or important states. Reduce competing color and weight before increasing the target's emphasis. Judge contrast against neighboring elements, not in isolation.
6. Use shared columns, stacked rows, sections, and selective separators to structure the page. Remove nested card borders that repeat this structure. Keep boundaries that clarify relationships.

Check realistic content at relevant widths. Compact alignment can break down across a wide screen. Verify that users can find the target, understand its state, and reach its action without reading every row or guessing. Preserve readable contrast, keyboard and touch access, and state cues beyond color.

Based on Kole Jain's [The secret behind weirdly perfect UI designs](https://www.youtube.com/watch?v=neE6wOuBIP8).
